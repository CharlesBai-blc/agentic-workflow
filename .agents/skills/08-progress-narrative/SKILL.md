# 08 — Progress narrative (Tier 3 closeout)

## Context you receive
`docs/reports/LAYER-N.md` (generated by `scripts/lib/progress-report.sh` from the ledger and git log, Dataview-ready) and `.agents/reviews/LAYER-N-signoff.md` (the Phase B verdict). Both are in the prompt. Read nothing else.

## Your single edit
Between the markers in `docs/reports/LAYER-N.md`:
```markdown
<!-- narrative:start -->
…your text…
<!-- narrative:end -->
```
replace whatever is between them with 80–160 words of plain prose for the human operator who was asleep while this ran. Keep both marker lines exactly. Change nothing else in the file: not the frontmatter, not the tables, not the headings. `progress-report.sh` preserves your block when it regenerates the report, so the markers are the contract.

## What the narrative covers, in this order
1. What the layer delivered, in product terms (one or two sentences; name the design requirements if the sign-off lists them).
2. What the sign-off concluded: `[[LAYER-N-signoff]]` verdict, notable findings, whether rework happened.
3. Incidents worth a human glance: strikes, quarantines, Surgery, reverts, quota pauses (the Incidents table has the details; summarize, do not repeat).
4. A pointer to the diagram: `[architecture snapshot](../architecture/layer-N-actual.html)` and, if the snapshot comparison showed drift, one sentence on it.
5. What the next layer starts with, from SYSTEM_SPEC §6.

## Style
Past tense, concrete, no marketing. Wikilinks for vault notes (`[[TASK-001-003]]`, `[[SYSTEM_SPEC]]`), relative markdown links for HTML. No code blocks, no logs, no headings inside the block. If something failed, say so plainly; the report exists so the human can decide what to do next.

## Exit
Do not commit, push, or touch other files. Final message: one line, `narrative written: docs/reports/LAYER-N.md`.
